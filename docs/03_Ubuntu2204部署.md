# RK3588 Ubuntu 22.04 部署

## 文件和依赖

复制整个项目，保留目录结构。在有写权限的位置解压，终端进入项目根目录。以下命令都以项目根目录为当前目录；掩膜路径也相对这里。

```bash
bash scripts/install_ubuntu2204.sh
```

脚本安装 apt 的 OpenCV/NumPy/SciPy 和系统视频工具，再建立使用系统包的虚拟环境，安装 pymavlink 等依赖。这样不强行用 pip 的 x86 或通用 wheel 替换板卡已经配置好的 OpenCV。安装过程需要网络。如果板卡厂商已有定制 OpenCV，可手动复用，确认 `import cv2` 和 `cv2.aruco` 正常。

Python 最低 3.10，OpenCV 最低 4.5.4。已测试 Windows x86_64、Python 3.12.14、OpenCV 4.11.0，以及 Ubuntu 22.04 WSL x86_64、Python 3.10.12、发行版 OpenCV 4.5.4、NumPy 1.21.5、SciPy 1.8.0。两边均通过完整测试；WSL 中也成功编译运行 V4L2 ABI 探针。真实 RK3588 ARM 和相机 ioctl 路径仍未实测。安装脚本会在目标机重跑测试和本机 ABI 探针。

## 先跑离线演示

```bash
bash scripts/run_demo.sh
```

输出在 `data/synthetic_demo/`。用浏览器打开 `report.html`，检查 72 方向输出和四张输入图。`benchmark.json` 是该台机器的静态帧计算耗时，仍不包含相机/飞控延迟。

已有四目数据可离线运行：

```bash
.venv/bin/python -m omniavoid replay \
  --config configs/rig.calibrated.json \
  --manifest data/real_recording/manifest.json \
  --output logs/replay.jsonl --html logs/replay.html
```

manifest 示例见 `examples/synthetic_demo/manifest.json`。每组含四个相机名到图片相对路径的映射、递增 `timestamp_ns`、`sequence` 和帧间 `skew_ns`。回放不连接飞控，也不会因文件时间戳碰巧接近当前时间而发送。

## 相机驱动与节点

Ubuntu 22.04 只是用户空间版本；相机能力取决于厂商内核、设备树、传感器驱动、ISP 和板卡线路。先确认板卡实际引出的 CSI 路数、OV9281 驱动、四路硬件触发和供电。

```bash
v4l2-ctl --list-devices
media-ctl -p
v4l2-ctl -d /dev/video0 --all
v4l2-ctl -d /dev/video0 --list-formats-ext
```

对每个物理相机找出真正的图像输出节点，不要把统计或同一相机的另一个输出路径当作第二个相机。四路可以建立 udev 稳定名称，再写入 `capture.devices`。`/dev/video0..3` 只是示例。

本采集器支持 64 位 Linux 的单平面及多平面 mmap：GREY、YUYV、Y16（fourcc 为带末尾空格的 `Y16 `）、NV12/NV21 和多平面 NM12/NM21。NV12 类只提取 Y 灰度平面，Y16 按 `y16_shift` 右移到 8 位。字节步长和多平面 data_offset 取自驱动。

OV9281 传感器可输出 RAW8/10，但实际 V4L2 fourcc 不一定叫 GREY。若 BSP 暴露 packed RAW10/RAW12、专用压缩格式、不同 Bayer/mono 标记或不受支持的布局，需要增加明确的解包适配器，或者选择合适的 ISP/luma 输出路径。**不自动把未知原始格式当灰度读。**

帧率、曝光、增益、外触发、镜像和 ISP 图像处理由厂商工具、v4l2 controls/子设备或驱动配置。`capture.fps=30` 是配置记录，代码不会假装已经给所有传感器设置了 30 fps。匹配相机宜统一曝光、增益和 ISP 处理，减少亮度及滤波差异。

## 只运行感知，不发飞控

真实配置应包含实测内外参；制作方法见标定文档。

```bash
.venv/bin/python -m omniavoid inspect --config configs/rig.calibrated.json
.venv/bin/python -m omniavoid run --config configs/rig.calibrated.json \
  --duration 60 --output logs/bench.jsonl
.venv/bin/python tools/analyze_log.py logs/bench.jsonl --output logs/bench_summary.json
```

重点看 `age_ms`、`skew_ms`、处理耗时 P95/P99、缺测比例和 `processing_deadline_missed`。20 Hz 是发布目标，独立新结果可能更慢；重复发送同一采集时刻的数据不能算新增感知帧。

## 开启 MAVLink

编辑 `mavlink.endpoint`：UDP 用 `udpout:目标IP:端口`；串口用 `serial:/dev/ttySx`，并设置 `mavlink.baud`。示例为 460800。飞控侧端口也要配置对应协议与波特率，确认电平及 GND。不要猜板卡 UART 对应关系。

已完成实物验证后，配置要求：

- `calibration.synthetic=false`。
- `calibration.validated=true`。
- `calibration.body_alignment_verified=true`。
- `calibration.occlusion_masks_verified=true`，表示已经检查安装后的可用像素和遮挡；有遮挡时提供各相机 `valid_mask_path`。
- `capture.hardware_sync_verified=true`。
- `capture.exposure_timestamp_verified=true`。

这些是实际验证结果的记录，不是为了通过程序检查而随手打开的开关。验证完成后：

```bash
.venv/bin/python -m omniavoid run --config configs/rig.calibrated.json \
  --transmit --output logs/live.jsonl
```

本地接收检查工具：

```bash
.venv/bin/python tools/mavlink_monitor.py --host 127.0.0.1 --port 14550 --duration 30
```

它只接收。正式端到端验证应查看飞控内部 proximity/obstacle 数据与制动响应，而不只看直接 UDP 接收器。

## 性能调优次序

先保持正确性，测完整年龄分布及热点。默认一个 pair worker、OpenCV 4 线程；可测 `pair_workers=2` 与较少 OpenCV 内部线程，避免线程过量。核查实际 CPU 拓扑、散热和降频，不在脚本里强行锁频或关闭温控。

降低虚拟图分辨率会减少远处视差，可靠测距范围也会变短；减少视差范围会加大近场盲区。降低 `point_stride` 只改变点采样，不能减少 SGBM 的主要代价。不要为了显示 20 Hz 简单放宽过期时间或取消左右一致性。

后续优化可以把固定映射移到板卡支持的 FEC/OpenCL，或把热点迁到 C++。本版不预设这些硬件后端已经可用；NPU 6 TOPS 也不会自动加速 SGBM。

## 常驻服务

`deploy/omniavoid.service.example` 只是模板，默认不发送飞控。需自行安排项目路径、`omniavoid` 用户、video/dialout 权限及 logs 写权限，再手动安装服务。不要在标定和验收前启用开机发送。

该服务用 SIGINT 正常退出；掉电、强杀和硬件故障仍需飞控侧失效处理。健康状态没有自动接管飞控的含义。
