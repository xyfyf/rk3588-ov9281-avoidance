# 在这台电脑上仿真与检查实时性

此处测试目标是当前电脑，CPU 为 Intel Core i7-12700K，具备 NVIDIA RTX A2000，但当前 OpenCV CPU 算法未使用 GPU。日期按用户本地时间为 2026-11-03，America/Denver。

## 能直接打开的仿真

双击项目根目录 `打开动态仿真.cmd`，或浏览器打开 `examples/realtime_20261103/simulation.html`。网页完全离线，展示已经实际计算的帧，可选择场景、拖动时间轴和播放。

场景包括：

- 机体逐步接近箱体，由四张真实几何投影的鱼眼图输入当前测距算法。
- 原地偏航，检查障碍方位随相机朝向变化。
- 前相机黑帧及低纹理表面，检查未知方向增加。
- 初速 1 m/s 和 3 m/s 的一维点质量制动演示，算法输出参与简化控制。

**这些是算法级动态图像仿真和简化闭环，不是 PX4/ArduPilot SITL。**两种飞控固件都未参与本次闭环计算，未知时制动是本演示的自定义策略。点质量模型没有姿态、电机、桨盘、风和真实飞控响应。

点质量仿真假设测距周期 0.1 s，采集到控制延迟 0.15 s，制动减速度 1 m/s²，余量 1 m。模型时间与实际计算耗时分开记录；网页按模型时间播放，不代表整个 CPU 渲染器实时跑到了这个帧率。

动态图像为了缩短渲染时间，采用每路 640×400 输入和相同 384×192 虚拟双目图；性能基准另用完整每路 1280×800 输入。两者不能混淆。渲染器的 CPU 时间单独统计，真实相机采集不会运行这个渲染器。

## 重新计算

Windows 可在项目根目录用 PowerShell 运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/launch_simulation_windows.ps1 -Recompute
```

脚本会建立项目 `.venv-pc` 并安装依赖，需要本机 Python 和网络；仅查看已有回放无需安装依赖。这里只对该次脚本调用设置执行选项，不改变系统策略。

Ubuntu 环境安装依赖后：

```bash
.venv/bin/python tools/benchmark_realtime.py --iterations 150 \
  --output data/pc_benchmark.json
.venv/bin/python tools/simulate_motion.py --output data/pc_motion \
  --benchmark data/pc_benchmark.json
```

工具默认四组相机对并行、OpenCV 内部单线程；可用 `--pair-workers` 和 `--opencv-threads` 修改动态仿真线程配置。这个配置针对当前电脑验证，未改动 RK3588 的通用默认配置。

只测最佳组合的持续计算：

```bash
.venv/bin/python tools/benchmark_realtime.py --iterations 1000 --profiles 4:1 \
  --output data/sustained.json
```

动态仿真工具可加 `--sustained data/sustained.json`，把持续测试汇总显示到网页。只选择一个线程组合时仍输出统一的 profiles 格式；网页也兼容本次已保存的单组汇总格式。

## 计算实时性与控制实时性

四目图算一次 50 ms 对应最高约 20 次新测距/秒。相机曝光、读出、数据传输、排队、操作系统调度、MAVLink 通信和飞控制动还要消耗时间。20 Hz 发布线程可以重发同一旧测量，不能把消息频率当成新深度帧频率。

本次微基准对四种线程组合各运行 150 次，输入图固定不变，保持相同算法和筛选，不通过降低分辨率、取消左右一致性或放宽过期时间来获得更快结果。记录中位、P95、P99、最大值和超 50 ms 比例。原始数据见 `benchmark_full_resolution.json`，持续测试见 `sustained_1000_frames.json`。

这些是普通桌面系统、当时负载下的软实时观测，不构成最坏执行时间保证，也不能推出 RK3588 性能或真实飞行最高速度。动态场景数据用于补充固定图的局限，但仍只包含合成材质和理想同步。

## 本次结果

四组相机对串行、OpenCV 内部 4 线程：150 次中位约 55.2 ms，P95 59.5 ms，每次均超过 20 Hz 对应的 50 ms 预算。默认配置在这台电脑上不能称为稳定 20 Hz 新测距。

四组相机对并行、每组 OpenCV 内部单线程：保持同一算法与质量筛选，150 次中位约 27.0 ms、P95 32.1 ms。另连续运行 1000 次，中位 27.4 ms、P95 33.8 ms、P99 38.4 ms、最大 48.8 ms，1000 次均未超过 50 ms。固定图像计算平均约 35.5 Hz，但未包含实际相机链路和控制。

动态仿真共 94 组四目图；各场景处理 P95 约 31～41 ms。每组 CPU 渲染本身中位约 0.32～0.34 秒，明显慢于测距，因此本次完整渲染＋测距不是实时仿真，网页用已计算帧按模型时间回放。真实系统相机直接提供图像，不需要运行这个 CPU 渲染器。

在简化一维控制模型中，从距箱体 3 m 处开始，初速 1 m/s 最终停止在机体中心距箱体约 1.04 m；初速 3 m/s 则在约 1.16 s 与箱体接触。两者仅说明该模型假设下的制动结果：传感周期、延迟和减速度都是设定值，没有真实飞控或飞机参与。

四组并行输出与串行输出经过同一组图像逐项测试，距离、未知分区、支持点数和三维点一致。未为了测速减少左右一致性筛选、降低虚拟图分辨率或改动匹配范围。复杂真实场景仍可能有不同运行时间及检出率。

接近箱体序列也暴露了质量问题：25 帧中，3 帧前向不可用；2 帧的前向保守距离低于真实箱体间距的一半，例如真实 3.00 m 时输出 0.86 m。保守下界本身就会偏小，但如此明显的偏近还需要排查错误匹配、点簇支持和不确定度模型，不能当作精确测距。真实间距约 0.6～0.7 m 时出现未知，符合近场可用重叠不足的风险。网页提供真值、前向五格最小输出和正前方单格输出的逐帧对照。上述结果支持继续开发和测量，尚不支持宣布算法已具备可靠飞行避障能力。
