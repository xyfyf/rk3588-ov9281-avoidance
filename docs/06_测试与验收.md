## 目标机验证顺序

1. 验证四路稳定采集与硬件触发。用可计时 LED/示波器、曝光信号或合适的同步实验，确认曝光时间对齐和内核时戳语义，不只比较应用收到图片的时间。
2. 完成内外参、相机到机体系对齐、实际遮挡掩膜和独立尺度测量；画出不同距离处真实双目可用角区。
3. 静态目标覆盖前后左右及对角方向，逐步接近到盲区；包含无纹理墙、柱、网、细线、玻璃、反光和低照度，记录漏检/误检，而不只数有效格。
4. 在 RK3588 长时间运行，记录温度、频率、帧率、分区缺测、处理 P95/P99 和最坏年龄。人为停掉相机、堵塞处理和断开链路，分别核实发布状态及飞控响应。
5. 对 PX4 和 ArduPilot 各做一次 SITL/不装桨的方向、消息和控制模式验收，再到合适的受控实机环境验证低速制动。
6. 从很低速度逐级验证，先以 0.5 m/s 左右作为测试起点；这是试验安排，不是当前已保证的速度。近场 ToF 等补盲传感器也要验证融合、坐标和失效行为。

## 速度怎么算

静态障碍、保守可用减速度 a、端到端延迟 τ、距离余量 M 下，需要可靠探测距离 D 满足：

`D ≥ v·τ + v²/(2a) + M`

从该模型得到：

`v ≤ -a·τ + sqrt((a·τ)² + 2a(D-M))`

使用工具：

```bash
.venv/bin/python -m omniavoid speed-estimate \
  --distance 3 --delay 0.2 --deceleration 1 --margin 1
```

该组假设的数学上界约 1.81 m/s，**不是本设备推荐速度**。D 应来自困难场景下的可靠检出距离，τ 包括曝光/读出/排队/计算/传输/飞控响应的保守估计，a 来自当前载荷下的实机制动，M 包含尺寸和额外余量。

移动障碍、侧向接近、风、姿态变化、时戳误差、控制饱和和漏检不由此简化模型保证。四个方向的可靠距离与制动性能可能不同。未实测前不能依据 NPU TOPS、传感器最高 FPS 或某次最远匹配距离宣称能飞 3/5/10 m/s。
