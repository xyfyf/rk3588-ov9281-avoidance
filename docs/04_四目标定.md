# 四目鱼眼标定与遮挡掩膜

## 安装和标定板

相机安装要刚性固定，先锁好镜头焦距和螺纹，记录每个相机的实际图像方向及机架位置。重新调焦、旋转镜头、改变图像裁切或移动相机后重新标定。

本包用带独立 ID 的 ArUco GridBoard，避免普通对称棋盘在不同相机里出现角点顺序翻转。板为 7×5 个 marker，单个黑色 marker 边长 30 mm、间隔 7.5 mm，含白边的整张图为 275×200 mm。

```bash
.venv/bin/python -m omniavoid make-board --output calibration_board
```

打印 `aruco_grid.png`，按 `board.json` 的精确毫米尺寸输出，关闭“适应页面”，贴在足够平整的板上；用尺子检查多个 marker。打印比例错误会直接造成米制测距尺度错误。不要凭 PNG 屏幕显示大小估计物理尺寸。

## 数据采集

先在配置中填正确设备、输出尺寸和接近真实镜头的初始内参；示例 fx 只适用于理想 200°等距镜头。若厂家有标定，应先转换模型并核实单位，不直接混用普通 Brown 畸变和 KB4 系数。

```bash
.venv/bin/python -m omniavoid record --config configs/rig.example.json \
  --output data/calibration_capture --samples 160 --interval 0.5 --timeout 300
```

录制时依次给每个相机提供不同距离、俯仰、旋转和位置的清楚板图；每个相机至少需要 12 个可用姿态，实际建议更多。单张要识别至少 3 个 marker。几乎相同的板姿不能有效约束内参。

每组相邻相机都要有多次同时看见同一块板的静止姿态，构成前右→右后→后左→左前连通图。拍摄过程中机架不动，板停稳再保存；如果尚未证明曝光同步，只能在板和机架都静止时采集，不能靠帧时间戳为移动标定板制造虚假对应。

鱼眼外缘必须有足够观测。只在图像中心拍几十张并不能标定 >90°的后半球。原始鱼眼上的 marker 检测可能在严重弯曲边缘失败；需提高板成像质量、增大 marker 或使用适合的检测/专业标定工具，不应强行扩大 `max_theta_deg`。

## 求解

```bash
.venv/bin/python -m omniavoid calibrate \
  --config configs/rig.example.json \
  --manifest data/calibration_capture/manifest.json \
  --output configs/rig.calibrated.json
.venv/bin/python -m omniavoid inspect --config configs/rig.calibrated.json
```

流程先检测 marker ID 和角点，使用全角度 KB4 模型分别优化内参和各帧板姿，再固定第一相机为机体锚点，联合优化其他相机外参和板姿。采用鲁棒损失和稀疏最小二乘；径向函数必须保持单调。

输出仍是 `validated=false` 的候选。优化器成功和较小重投影 RMS 不证明外缘已充分观测，也不证明所有镜头偏差都符合 KB4。单一 `observed_max_theta_deg` 只约束最大观测角，不能证明每个方位角都同样可靠。

候选会把 `max_theta_deg` 限制在实际观测范围，可能导致环向覆盖下降，这是需要补拍或更换方案的证据，不能简单把它改回 100°消除警报。

## 机体锚点与尺度验证

第一相机 `R_body_from_camera` 和 `t_body_from_camera_m` 是用户给定的固定锚点，不是通过视觉自动估出的飞控 IMU 对齐。需要测量机体前向、水平、相机中心与飞控/机体中心的关系，才能将距离正确发送为 BODY_FRD。

测量相邻相机物理中心间距，与解算外参对照。再用独立卷尺/测距仪，在前、右、后、左及中间方向布置有纹理目标，覆盖近、中、远多个距离。同时检查虚拟双目图里同一点是否在同一行，以及重建点是否落在正确机体方向。

默认输出是减去不确定度后的保守距离下界，不能直接把它当未修正的深度值做相机精度拟合。需要检查 `cloud.npz` 或实际回放点云的原始三维距离，再分别记录深度误差与最终障碍距离余量。

## 遮挡掩膜

```bash
.venv/bin/python tools/create_masks.py --config configs/rig.calibrated.json --output masks
```

该命令生成理想镜头有效域模板，不会自动识别真实机架。查看真实图像，把线束、机架、旋翼扫过区域、镜头黑边及质量不合格区域涂黑，其余保持白色。每张 PNG 尺寸要与原图完全一致。

在对应相机配置中添加，例如 `"valid_mask_path":"masks/front.png"`。从项目根目录运行，使相对路径一致。代码会拒绝缺失或尺寸错误的掩膜。

重新运行 `inspect` 和多方向距离测试。掩膜减少视野是正常现象；不要为了让覆盖看起来完整，把实际被遮住的像素标为白色。完成安装后真实有效域检查才记录 `occlusion_masks_verified=true`。

## 如果本工具求解失败

常见原因是图像方向/尺寸不一致、镜头初值太离谱、marker 过小或模糊、只有中心视图、姿态缺少变化、相邻相机没有共同板观测，或实际镜头无法用当前模型充分拟合。

本版内参初始化使用前半球可见角点做 PnP，因此仍需要中心/前半球板姿；它不是任意坏初值都能收敛的通用标定软件。也可以用经过验证的第三方 KB4 标定工具输出内参和刚体外参，再按这里的坐标定义转换，最后做同样的尺度、覆盖和飞控方向验收。
