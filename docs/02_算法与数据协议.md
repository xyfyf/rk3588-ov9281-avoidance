# 算法、数据及失效处理

## 坐标和输入

机体系为 FRD：x 前、y 右、z 下；相机坐标为 x 右、y 下、z 光轴前。配置中的旋转 `R_body_from_camera` 和平移 `t_body_from_camera_m` 将相机坐标转换到机体系，平移单位米。镜头使用 KB4：`intrinsics=[fx,fy,cx,cy]`，`distortion=[k1,k2,k3,k4]`。

输入是四张已匹配时间的 uint8 灰度图。分辨率必须与对应标定一致，不允许悄悄缩放、裁切、镜像或旋转。实际修改这些项后必须同步修改内参/外参或重新标定。

## 全角度鱼眼模型

对相机点 (x,y,z)，设 ρ=sqrt(x²+y²)，θ=atan2(ρ,z)。畸变半径为 θd=θ(1+k1θ²+k2θ⁴+k3θ⁶+k4θ⁸)，像素为 (cx+fx·θd·x/ρ, cy+fy·θd·y/ρ)。用 atan2 保留 z<0 的后半球角度；θ>90°不会被折回前方。

只使用已标定角度范围，并减去 `rim_guard_deg`。径向函数必须单调；逆投影通过有界二分求解。可选 `valid_mask_path` 是与原图同尺寸的 PNG：白色可用、黑色排除。机架、线束、旋翼和质量不达标的边缘应排除。路径相对项目运行目录。

## 虚拟双目

相邻相机四组为前右、右后、后左、左前。每组虚拟 x 轴沿两相机中心基线，z 轴取相机光轴和在基线正交平面上的归一化投影，y=z×x。这样两个虚拟相机具有相同旋转、相同焦距，中心只沿虚拟 x 轴平移，极线保持水平。

启动时预计算重投影映射；每帧使用 remap 生成虚拟图。默认每幅 384×192，水平 FOV 110°；像素仍需通过两相机的有效掩膜。虚拟针孔图不等于原鱼眼的所有区域都可测。

## 匹配和质量筛选

分别计算左→右正视差与右→左负视差。OpenCV SGBM 的定点输出除以 16；右匹配范围按负视差设置。保留有效重投影区域、纹理方差达标、视差在搜索范围内且左右一致的点。掩膜边界向内腐蚀，减少黑边及遮挡影响。

虚拟深度 Z=fB/d；还原三维坐标后转到机体中心。左右两个参考视图都重建，以减少单侧视差搜索造成的边界损失。计算视差噪声假设下的距离不确定度，σr≈r·σd/d；相对不确定度超过阈值的点丢弃。

`disparity_sigma_px` 是需要实测调整的工程假设，不是经过概率校准的置信度。标定偏差、系统性错误匹配、光学非中心效应等不能靠这个公式保证覆盖。

## 水平分区

将点按机体系高度带筛选，默认 -0.6≤z≤0.6 m，再按水平半径和角度分到 72 格。第 0 格中心朝前，正方向顺时针；正右/正后/正左对应 18/36/54。每格覆盖中心角 ±2.5°。

每格按距离排序，寻找最近且满足最少点数与径向跨度要求的点簇；选择该簇最小的“距离减若干倍不确定度”作为保守下界。负数饱和为零，转厘米向下取整。默认 `reject_unconfirmed_foreground=true`：如果前面还有明显更近但没有得到点簇支持的返回，整格标为未知，不用远背景覆盖潜在的细小前景。完全未匹配出的细线、小障碍仍可能漏检，需在验收中测试。

`range.min_m/max_m` 是三维候选点筛选范围，不能当成真实可保证的测距范围。下界经过保守修正后可能低于 `min_m`；消息 `min_distance=0` 允许这些下界，不代表传感器可以测到零距离。内部结果保留饱和0；v0.2.1起，正式MAVLink编码器将0映射为1 cm，因为本次测试的定制ArduPilot会忽略0、接受1。这是最小正值的兼容表示，不承诺厘米以内的测量精度。

默认不使用时间平滑、历史自由空间填充或远距离值补洞，不缓存旧障碍到新位姿。可选角向膨胀默认为 0，避免与飞控安全余量无意重复；启用后需统一机体尺寸与飞控 margin 的定义。

## MAVLink 2

消息为 `OBSTACLE_DISTANCE`（ID 330）：

- `distances`：72 个 uint16 厘米值。
- `increment=5`、`increment_f=5.0`，默认 `angle_offset=0`。
- `frame=MAV_FRAME_BODY_FRD`，实际线缆传输中保留扩展字段。
- `time_usec`：源图像采集时间对应的 Unix 微秒；正常重复发布不把旧测量改成新采集时间。
- `max_distance`：配置上限；`min_distance=0`，原因见上。
- 65535：未知/未使用；内部0表示接触/保守下界饱和，线上编码为1 cm，避免接收端丢弃。其余有效值不变。

协议的 `max_distance+1` 代表范围内无障碍。**本算法不输出该值**，因为立体失配或没有点不足以证明一整格自由。前方远墙的有效深度仍是一条障碍距离，不是“整条通道没有漏检”的证明。

发送器默认 sysid=191、compid=196，与飞控本身区分；按机载网络分配避免冲突。无签名时该消息完整帧约 179 字节，20 Hz 约 3.58 KB/s，另有少量心跳/状态。TTL 串口的电平、布线和端口应按板卡/飞控手册确认。

## 同步、过期和故障

V4L2 读取真实内核时间戳及序号；要求 CLOCK_MONOTONIC。有限队列按时间匹配，每次选择最新完整帧组并丢弃更早组，避免处理速度低于相机速度时持续追赶旧帧。拒绝重复/倒退序号、过期帧和异常未来时间；默认帧间差不超过 2 ms。硬件触发、共同曝光、时间戳参考点仍必须物理验证，时间差接近不等于已经同步。实时日志与录制清单保留各相机序号和 V4L2 时间戳 flags，便于检查 SOE/EOF。

Linux 官方区分 SOE（曝光开始）和 EOF（帧末）。后者可能比真实曝光晚一个读出/曝光周期。本实现不会自动把 EOF 猜成 SOE；如驱动只提供 EOF，应先在 BSP 中提供可用的曝光时间戳，或写经测量验证的时间补偿适配器。未核实时不得置 `exposure_timestamp_verified=true`，也不得用进程收到图像的时间替代曝光时间。

MAVLink 发布独立于图像处理线程：结果年龄从最早源图像时间计算；处理堵塞后超过上限即发布全未知。相机错误、处理异常、串口失败会退出或清空有效结果。退出时尽力发一次全未知；掉电、进程强杀、网络中断无法保证发送，因此必须验证飞控自己的失效策略。

**全未知、伴随计算机 critical 心跳或状态文字不是通用停车命令。**PX4 与 ArduPilot 可能保留旧值至内部过期，且无数据后的控制策略不同。需要分别验证，不能用发布线程的测试代替控制验收。
